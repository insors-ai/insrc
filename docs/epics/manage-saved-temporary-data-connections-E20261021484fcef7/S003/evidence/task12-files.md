# S003 task 12 — owner-private file execution

The existing sc8 memory execution and native/typed converter implementations are retained. A private WeakMap on daemon-minted factory contexts supplies the owner retention callback before source access or engine allocation. The file factory transfers each engine immediately after opening, before constructing/publishing its driver. Late allocations remain owned when authority expires. Owner stop interrupts file executions before awaiting callback drains; failed close retains the cleanup handle and blocks new admission.

The production 256MiB cap, no-spill engine, no persistent converter cache and no INSTALL behavior are unchanged. Fixed resource-limit and unsupported-temporary codes now survive private file error mapping; source-owned error text remains fixed. Existing saved/probe file contexts remain compatible and do not require the session retention port.

Five new cases exercise actual CSV, TSV, JSON, JSONL, NDJSON, Parquet, Avro, BSON, fixed-width and XLSX resources for two owners, with cross-root CSV isolation. They inspect engine settings and policy owner/root/id/revision, distinct rows/instances, recursive filesystem snapshots and observed writes, zero INSTALL, unsupported Arrow/Feather, oversized BSON framing, a running native query interrupted by end, and late allocation both before and after driver construction. Closed resources report zero tables/connections/operations/decoder bytes. Fixture Parquet/Avro creation finishes before snapshots.

The focused new/private-resource/factory suite passes, along with existing sc8 file-execution tests, session inventory and the updated acquisition/field audit. Build passes.
