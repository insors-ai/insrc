# S003 task 7 — session tickets and replay truth

Each session owns a private ledger using its reserved 256-bit memory key. Ticket and request HMAC domains include the server session handle and daemon epoch. Structural validation and bounded canonical request JSON reuse sc2 helpers; saved keychain ticket-key initialization and durable receipt storage are excluded. Wire dates derive from a session wall-time base plus the monotonic clock. Signed expiry is bounded by both 90 seconds and the then-current session lease; heartbeat never extends an existing ticket.

One bounded capacity of 16,384 operation records covers live issued tickets and committed receipts. Only expired uncommitted slots may be reclaimed; in-flight slots and committed receipts are not evicted. Records contain expiry, request MAC, in-flight promise identity and safe outcome only. Request MAC is pinned on first mutation admission. Concurrent identical requests share one actual application; changed payload refuses. Entry generation/revision publication and receipt publication occur in one guarded synchronous turn after preparation and root serialization. Activation phase is separately updatable and does not erase committed registration truth. Driver activation remains pending until the later runtime task.

Strict temporary ticket/mutate/status/read adapters now use live owner/root/generation/audience checks. They remain gated by disabled release evidence. Unattached clients cannot access the ledger; mcp-unverified data transports refuse before ledger or entry access. The shared saved-root serialization primitive is reused without saved IO. Saved/temporary collision and alias guards are the next task; no end-user temporary capability is released here.
