# Public endpoint safety grammar

This consumer boundary screens public connection fields. It does not determine driver URL validity, establish connectivity, normalize configuration, or authorize a connection. Those remain daemon responsibilities. TypeScript `wire.ts` and Kotlin `ConnectionProtocol.kt` implement the same grammar; policy revision 2 and 77 `endpointCases` in the versioned, digested shared corpus define its regression contract. The wire protocol and corpus envelope versions are unchanged.

- An endpoint value must be a string with absolute ASCII `scheme://authority` syntax. Preserve accepted text exactly; never trim, decode or rewrite the returned configuration. Opaque and nested SDK strings such as `jdbc:postgresql://…` are refused; their credential syntax is never guessed.
- Refuse raw C0/DEL/C1 controls, unpaired UTF-16 surrogates and backslashes. Authority must be nonempty except for `file:///…`. Missing/extra-slash and backslash spellings that a browser might normalize are refused consistently.
- Screen the authority before the first `/`, `?` or `#`. Refuse user-info `@`, authority delimiters, controls, Unicode whitespace and unsafe authority punctuation, including percent-encoded forms after bounded strict decoding. Authorities such as underscore hosts, IPv6 and multi-host driver addresses are structurally supported; their operational validity is a daemon decision.
- Preserve accepted path/query/fragment Unicode and escapable punctuation, including spaces, braces, literal percent signs and repeated `#`. Existing strict UTF-8 percent decoding, recursive secret-reference and private-field checks still run on the original configuration; malformed encoded bytes and excessive decoding depth are refused. This is a safety grammar, not full WHATWG or RFC URL conformance.

The shared cases exercise safe read, whole-list decode, public patch and nested option patch in both runtimes. Cross-language parity compares every verdict, including a divergent-consumer negative control. Fixtures contain synthetic data and confer no authority. No wire envelope, stored schema, session ownership or driver contract changes.

Compatibility is explicit: `driver-profiles.ts` already requires hierarchical syntax in `uri()`/`address()`. Unsupported raw SDK dialects stay server-owned: `projected()` marks them read-only and omits their endpoint, so clients can still read the safe metadata without exposing or rewriting the original string. A producer/consumer regression verifies this for opaque PostgreSQL and Oracle inputs. The producer also allowlists represented URL query parameters and refuses query-bearing option addresses; the client does not substitute a protocol-specific query parser for that producer contract. Ambiguous browser-normalized forms are refused by both clients, while accepted query/fragment text no longer depends on Java URI strictness.

The producer and TypeScript consumer share the pure `endpoint.ts` authority predicate. Projection omits any URL endpoint that fails that predicate and marks the metadata read-only, retaining the stored configuration. The producer’s existing strict recursive percent/reference check also applies before projection. This prevents a malformed saved path from invalidating the client’s whole list. Native parity continues to cover the same 77 client cases.

This boundary does not parse every credential-bearing SDK dialect or validate host/port semantics. Hierarchical strings with unsupported schemes, semicolon properties or nested content can pass the structural client patch check; daemon `materializeDraft` rejects them before mutation. Likewise `options.servers` and `options.hosts` have driver-specific syntax: daemon `address()` rejects userinfo in public patches and handles credential replacements separately. Regression cases exercise those authoritative rejection paths. Bare server/host addresses are valid for those option fields; `options.endpoint` belongs to DynamoDB and requires a URL.
