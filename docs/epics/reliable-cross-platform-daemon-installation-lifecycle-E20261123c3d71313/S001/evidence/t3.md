# s1/t3 — pinned private-runtime bootstrap

Added canonical POSIX and PowerShell release templates, a pure renderer, an independently recorded official six-target Node 22.22.1 archive policy (matching npm 10.9.4), and an embedded dependency-free publication helper. Source templates refuse use until a publisher embeds target-bound control assets. No consumer runtime-policy override is accepted. t4 supplies the release assembly and per-target qualification admission; terminal interaction/TUI handoff remains t8.

Scripts remove NODE_OPTIONS/NODE_PATH before running Node, preserve even an explicitly empty CUDA-install variable and default skip only when absent. They require user-level stock extraction/hash/download tools, use HTTPS and bounded downloads, verify archive/control hashes before execution, and never use PATH Node/npm. Windows follows at most eight explicitly HTTPS redirects with a cancellation deadline and byte ceiling; it applies a current-user-only control-root ACL through .NET, without privileged commands.

Fresh verified runtime executes the inline publication helper. Exact runtime version/OS/architecture and npm version must match; only expected POSIX Node/npm/header/license trees are extracted, omitting command aliases. Runtime publishes under `<home>/runtimes/22.22.1/<target>`. Existing contents must match the freshly verified tree byte-for-byte; no existing runtime is overwritten. Bootstrap/native assets publish together under their digest-addressed immutable control directory. Unique incomplete stage directories are removed on normal success/failure/cancellation. No service installation, signing, global PATH change, npm install or compiler is introduced on consumers.
