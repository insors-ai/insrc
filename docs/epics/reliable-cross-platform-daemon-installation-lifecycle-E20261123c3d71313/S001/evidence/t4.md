# s1/t4 — release publisher and shared resource assets

Implemented the coordinated production publisher, ZIP/inventory assembler, installed production dependency closure, dependency-minimal control bundling, exact-target probes and client resource-copy integration. Pinned yauzl 3.4.0, yazl 3.3.1, esbuild 0.28.2 and yauzl types 3.4.0 explicitly. Standard ZIP libraries are used instead of custom archive parsing/writing.

Production entry requires real daemon/manager/terminal/TUI build entrypoints before proceeding, exact current committed source inputs, the independently pinned official runtime archive, native/live qualification matching target/runtime/binding digest, and actual runtime/native dependency probes. Runtime contents are extracted by the owned publisher from that verified archive rather than copied from an arbitrary host directory. The expanded runtime and original archive both enter the payload. npm is not invoked by consumers.

Inventory records every payload file's path/digest/size/mode and is independently hashed. The archive contains inventory.json but never its own archive digest; release.json is an external descriptor carrying that digest and the manifest. Required entrypoints/runtime archive must be represented in inventory. GitHub assets have target/release-specific names to avoid multi-target collisions. Qualified output is published from a same-filesystem staging directory; existing immutable release paths are refused.

Dependency collection retains installed production, optional and peer dependencies and nested native package versions. Links must remain in the source root; workspace dependency links must be declared and supply explicit production files. Escaping links/cycles, special files, case collisions and unsafe paths are rejected. Compiled daemon/TUI/assets remain in the full payload; bootstrap/manager are separate single-file bundles. Actual esbuild metadata rejects application DB/indexer/provider/daemon imports, nonminimal packages and unbundled third-party imports. Node built-ins remain allowed, including unprefixed CommonJS built-ins used by ZIP dependencies.

The existing client synchronization boundary now copies digest-verified canonical install.sh/install.ps1 and script version/source/hash metadata. Ordinary source client sync still retires old installer resources and preserves steering/unrelated resources. IDE packaging requires qualified release input. No native IDE terminal frontend was added here. There are no restored deprecated installer filenames.
