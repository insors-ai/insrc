# s1/t6 — manager controller and peer admission

Implemented the short-lived manager, ordinary machine entry, separate terminal capability/TTY gate, actual s1 bundle adapter and explicit required dependency/lifecycle/migration ports. Production composition includes bundle delivery only; absent owning sibling implementations report capability-unavailable before disruption. No real service is replaced by fixture or no-op success. Terminal interaction/TUI composition remains t8.

Ordinary dispatch always rejects install, including forged source/bootstrap/terminal flags. Only a nonserializable terminal admission issued after all three TTY checks reaches the internal install method. Inspect/check-upgrade are read-only; typed convenience methods expose inspection/UpgradeOffer, while the machine entry emits existing ManagerEvent shapes with bounded read-only summaries in message. Offer acceptance binds installation/home/current release/delivery and exact descriptor digest. Completed matching operation requests are idempotent; unfinished operations require explicit same-operation/candidate recovery.

Only ControllerStore writes controller.json, with native exclusion, expected revisions and current-snapshot checks. Preparation adapters receive a restricted lease without controller/operation metadata writers. Manager-owned intent/candidate/shutdown/admission records live in a separate protected operations namespace. Candidate alone owns journal and lifetime wrapper alone owns receipt. Before launch, admission durably binds operation/installation/candidate inventory/session/child/nonce/receipt path and controller revision; the live-owner callback verifies persisted admission and current ownership. No PID, lease-age, endpoint-disappearance or journal-only inference can authorize a new runner.

Quiescing consumes exact instance/completion evidence. Migration requires the natural-exit receipt, released ownership and exact ordered hook-test journal evidence, including empty-hook owner confirmation. Explicit recovery reuses validated prior completion, or needs positive owning-hook retry policy after observed failed child exit; held/unknown ownership or missing/mismatched evidence remains blocked. Activation requires exact ready installation/release/instance/session/inventory/endpoint/nonce. Selection commits atomically only afterward. Before-disruption failures preserve incumbent selection/running intent; post-disruption uncertainty stays blocked without automatic predecessor restart. Candidate files are revalidated after drain and before launch.
