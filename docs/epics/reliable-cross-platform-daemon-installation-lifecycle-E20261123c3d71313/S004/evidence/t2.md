# S4/T2 — live launch admission

Task: `TASK-c3d71313f34bce71-s4-t2`, insors-ai/insrc#297.
Source: approved S004 LLD6 and PLAN2; T1 passed registered validation.

The private S4 rendezvous wraps the manager-provided `assertLiveOwner` callback;
the callback stays in its process. Each request revalidates the exact immutable
LaunchAdmission and invokes that fresh assertion, consuming the existing
manager's OS-lock/controller/phase/revision checks. No shared contract or
controller writer changes were made. Existing shutdown forwarding is unchanged.

The session's three one-use barriers are `spawn`, `lease` and `stores`, in that
order. A private 256-bit capability binds a protected local endpoint and exact
session. Fresh request challenges bind replies. Frames, connection count and I/O
time are bounded; malformed/stale/replayed requests, cancellation and connection
loss fail closed without automatic retry. Socket paths derive from the selected
home/capability; no existing socket is unlinked or replaced. Actual Windows
pipe security/behavior qualification remains T12 work.

The final store-grant client additionally requires this process's real retained
DaemonDataLease and checks its exact selected installation before and after the
grant. A boolean or a lease belonging to another installation cannot substitute.
The successful current-owner final grant is the admission point; later manager
loss does not revoke already-admitted lifetime work. Loss beforehand denies
stores; the isolated child exits and its data lease releases on actual exit.

Extracted the existing T1 private-root check for reuse and added a bound-installation
lease assertion. The manager and rendezvous never acquire the daemon data lease,
open application databases or inherit/transfer the manager lock to a child.
The actual child retains the daemon lease until exit.
