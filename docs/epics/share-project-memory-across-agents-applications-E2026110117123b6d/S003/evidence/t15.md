# S3 task 15 — memory/index/queue isolation and support gates

The root integration test runs the real IndexerService full path, including
deleteEntitiesForRepo, over a registered tiny temporary repository and separately
redirected LMDB/Lance stores. It changes a function, verifies rebuilt graph entities
and removal of its old native vector, closes/reopens the stores, then removes ONLY
the isolated test index directories and registers/rebuilds them again. No existing
production index-reset helper was found; this is explicit test-only removal, not a
new reset API. Existing vector cache reset is required when reopening/removing test
stores; closeLanceConn alone only drops its connection reference.

The independently owned real memory store holds committed current content,
immutable source/evidence/revision history, terminal proofs and a closed-session
tombstone, plus one actual accepted unacknowledged old-lifecycle frame. After every
index operation and memory preflight, cold reopen compares all logical memory row
IDs/payloads/generation, three authoritative proofs, the exact pending frame and
segment byte hashes, accepted operation status, closed lifecycle eligibility and
current visible content. Memory/protection/proofs/pending bytes remain identical.
The cleanup preservation oracle includes nonempty real graph AND vector contents.

The sole S3 addition is private non-destructive preflightCleanupTarget. It accepts
only the exact canonical owned memory.lance directory after fresh root/lock and
directory inode checks. Root/queue/metadata/parent/child/foreign targets, lexical
and symlink aliases, symlink replacement and changed inode are refused. It calls
no unlink, purge, reset or native deletion operation, and grants no permission to
erase replay/deletion protections. Store rows and pending work survive all tests.

Two focused tests pass with zero skips (t15-tests.tap), and package/root typechecks
are clean. t15-isolation.json records Node/platform/filesystem, exact package and
relevant backend source hashes, SDK/native fingerprints, profile, operations and
the logical/queue oracle digest. A bare LMDB open and an unchanged existing rebuild
test abort inside the process sandbox; a bare temporary LMDB probe succeeds outside.
The real isolation test therefore ran outside the sandbox against only its new
temporary stores. No live index, settings or provider was changed/called.
