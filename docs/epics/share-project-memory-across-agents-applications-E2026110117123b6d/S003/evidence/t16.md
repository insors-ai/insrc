# S3 task 16 — measured resources and latency

The complete study passes all assertions. It ran on Apple M3 Pro, 12 logical CPUs,
36GiB RAM, macOS arm64/APFS, Node22.23.2 ABI127, Lance0.40.0/Arrow18.1.0. Source,
native binary, hardware, profile, safety limits, raw samples, counts and limitations
are in t16-resource.json; progress is in t16-resource.json.progress.jsonl. The fast
root evidence test independently verifies current source hashes, complete corpora,
exact quantiles/counts/progress and honest boundary outcomes. No skip or reported-only
result substitutes for that executable evidence check.

All corpus data is generated through real queue admission, production guarded
commits and durable ACK. No SDK bulk seeding or model call. The corpus uses distinct
synthetic keys, short repeated text and D=2 deterministic vectors, so these are not
production embedding/text/semantic-deduplication estimates. See t16-method.md for
reproduction and measurement overhead. There are five samples per latency cell;
p95 is the largest sample, not a statistical tail guarantee.

Opens are connection-cold in a warm process/SDK, including the full startup audit;
they exclude queue reopening. Commit figures include queue ACK, an explicit upper
bound on isolated store commit time. The 10k read figures measure refusal, not a
successful complete context operation; no context is silently truncated.

The study then committed 1,000 material history corrections and 1,000 exact memory
tombstones. End state has 10,005 current rows, 11,005 revisions/evidence rows each,
1,000 tombstones and 2,026 receipts after the boundary publication. Physical store
and queue logical file bytes total 326405747; allocated disk is 338928KiB. Canonical
receipt payloads account for 4066479 bytes and control payloads 712 bytes; these are
payload attribution, not a fictitious per-kind physical-file allocation.

Per-corpus RSS/heap-used snapshots were 162.31/34.67MiB empty, 158.25/22.55MiB at1k,
235.81/34.22MiB at10k, and 395.97/23.16MiB with history/tombstones. Sampled overall RSS
peaked at 666468352 bytes, heap-used at148794976 and heap-total at175013888; raw OS
maxRSS is separately recorded. Overall peaks include harness allocations, notably
oversized caller input and native-binary hashing. RSS-minus-heapTotal is explicitly
a native-and-other estimate, not isolated native allocator RSS or a64MiB RSS cap.
Dependency/native/license footprint is separately qualified in t14-package.json.

Boundaries all pass: 16 held leases and explicit 17th BACKPRESSURE; exact64MiB logical
reservation and one-byte overflow/refund; oversized64MiB canonical input rejected
before mutation; 4096 supplied effects rejected with generated-row reservations;
4093 source effects plus three generated rows committed in one4096-row publication.
The last case took520220.676ms including guards, publication verification and ACK
against the populated retained-history store. No successful64MiB native batch is
claimed. Source/profile/safety bounds and native-write timeout were not changed.

Performance is a material limitation: large cold audits and large populated-store
batches are slow. In the recorded100-operation cohorts, correction wall time grew
from21.684s to113.352s; tombstone cohorts grew from100.415s to221.874s. Those include
queue work/recycling and are not individual-call quantiles. No production latency
SLO is claimed, and no accuracy check was removed to improve measurements. Future
performance/maintenance work must preserve all source/receipt/deletion verification.

Package/root typechecks pass. t16-evidence-test.tap passes with zero skips. The study
is explicit hardware qualification outside the default regression glob, so the final
sweep verifies its source-bound evidence without needlessly repeating the hour-long
experiment. Final package/backend/APFS/ext4 sweeps and independent review remain t17.
