# S3 / t3 — native SDK primitive qualification

The test-only native harness uses the actual pinned Lance/Arrow packages,
explicit full row schema, a single standard-path merge, S1 ownership and parent
IPC observation of actual SIGKILL. It does not implement the production store
or use a fake receipt authority. Existing nativeTest/ownership fixtures and the
queue test's standard Node fork pattern were reused after analyzer discovery.

Local Node 22.23.2/macOS arm64 APFS run passed. See [TAP](t3-macos.tap) and
[fingerprinted report](t3-macos.json). It verifies mixed nullable vectors at
dimensions 2/1024/8192, scalar and temporal round-trip, pinned reader isolation,
one-version effects/receipt/control publication, normal reopen and eight real
process kills. The two deterministic before/after boundaries recovered old/new
respectively; the six delay races observed both old and complete new outcomes.
Delay races do not identify an internal Rust filesystem stage. This is process
crash evidence, not a host power-loss/fsync proof or the later t10 real
queue/store integration qualification.

The initial run [failed](t3-macos-first-attempt.tap) because an intentionally
waiting race peer could exit naturally before the parent's delayed SIGKILL.
Explicitly referencing its IPC channel fixes the test harness; failed runs are
not counted as qualification. The normal-exit parent still runs without
force-exit. nativeTest's existing runtime-child timeout remains unchanged for
all callers except this longer qualification case.

The manual project-memory workflow now has a focused store-sdk mode, preserving
full/queue modes, recording resolved dependency graph/lockfile and running no
backend sweep during task iteration. Linux/x64 ext4 Node 22.22.1 qualification
passed in [CI 41638575999](https://github.com/insors-ai/insrc/actions/runs/41638575999)
at candidate 24a61e760b4e8e10787e91e658db362e1d6ab254. The focused suite passed
all ten cases with zero skips, including eight real SIGKILL boundaries and all
three vector dimensions. Downloaded artifacts are in t3-linux; the source
fingerprint map matches the macOS report exactly. Native binaries are separately
fingerprinted for each platform. This closes the primitive platform gate only;
the production writer/queue integration gate at t10 remains outstanding.

The Node 26 test runner also passed through the existing supported-runtime
wrapper, executing the actual native case on Node 22 rather than loading an
unsupported host: see t3-node26-wrapper.tap. This does not qualify Node 26 as a
memory host.
