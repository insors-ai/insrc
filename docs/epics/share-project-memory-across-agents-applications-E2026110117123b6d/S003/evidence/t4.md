# S3 / t4 — owned initialization and safe reopen

Added private store format/init metadata and a lazy native resource owner. The
marker is UUID/profile/provisioning evidence only; generation authority stays
in the Lance control row. Marker replacement uses bounded private descriptor
reads and write/fsync/rename/directory-fsync, following S1's established pattern.
No queue or backend database is opened by this adapter.

Fresh initialization is limited to pristine S1 roots. Existing queue-only,
unknown, missing-ready-store and corrupted metadata/native states fail closed
without replacement or deletion. Recognized initializing state can resume only
an empty initial table/version or its single generation-zero control row.
Reopen checks profile/model/dimension/UUID/schema and refuses embedding callback
metadata. Unverified native cleanup is explicitly branded for the later host
composition to retain ownership; live native resources are strongly retained.

failed/skipped. They cover read-only reopen, queue-byte preservation, unknown
roots, missing marker/database/control, extra table, UUID/profile mismatch,
interrupted init, unsafe pending marker/directory, rollback boundaries and
two real failed-host peers (startup/close). Another owner is refused until
SIGKILL; cold reopen then succeeds. Package build passed. The initial fixture
used a noncanonical macOS temporary alias for a real S2 queue and failed its
existing canonical-root guard; [first output](t4-tests-first-attempt.tap) is
preserved, and the fixture now resolves the actual path before ownership.

Writer, proof/reader facades, lifecycle adapter and public host wiring remain
later tasks. The native primitive platform proof remains distinct from t10's
required production-store/queue integration qualification.
