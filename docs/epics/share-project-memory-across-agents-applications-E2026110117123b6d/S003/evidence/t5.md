# S3 task 5 — causal, reference and lifecycle guards

Implemented private CommitPlan snapshots and read-only guard evaluation. Reuses S2
canonical command/frame codecs and S3 row/profile codecs; no dependency, backend
import, native mutation, public export or host wiring is added.

`snapshotPlan` copies headers, admitted frame and rows independently, preserving
S2 payload depth/node capacity. It rejects getters, extra/missing fields, duplicate
keys, reserved generated rows, incompatible vector profiles, malformed terminal
dispositions and excess bytes/rows. It reserves row slots for generated receipt,
root and namespaces. Task 6 must also reserve the complete generated batch before
its single mutation. Prepared snapshots are registered by private object identity.

`guardEffects` requires exact generation/queue domain, per-current preconditions,
the command's explicit expectedRevision when present, predecessor/current pointers,
immutable history, same/narrower scope, same-namespace references and complete
revision/evidence/source sets. It derives source attribution/time/hash/span from
the strict final admitted envelope. Source/evidence IDs follow deterministic
qualified keys. Authority agrees with backing sources; source text is not fetched.
Reference reads/tombstone scans are bounded and unavailable authority fails closed.

All 42 status pairs have an independent normative matrix oracle. Reason checks
cover create/evidence-added/correct/conflict/resolve/supersede/expire/forget.
Evidence-only and lifecycle-only changes preserve embeddings; terminal transitions
preserve assertion content. Material revisions cannot reactivate terminal memory.
Paired supersession, carried evidence and exact logical forgetting have positive
and negative guard cases. Memory/source/subject protection is checked here; broad
source-lifecycle frame barriers and races remain task 8, not claimed complete.
