# S3 task 6 — sole atomic writer

The private AtomicWriter serializes admitted immutable plans, refreshes native
authority, reconciles existing exact receipts before causal stale checks, binds
queue identity on the first event and generates namespaces/receipt/root itself.
One standard mergeInsert (`useLsm(false)`) publishes the complete bounded batch.
No queue callback, ACK, model invocation or production MemoryFactory wiring.

OwnedLanceStore supplies private decoded native reads and the only production
mutation facade. Per-owner opening reservation prevents multiple store writers
under the same DirectoryOwnership. Startup streams narrow metadata and uses
native uniqueness checks, including receipt generation/identity coherence, without
retaining an unbounded JS history set. Duplicate/unknown metadata or missing
generation proofs refuses reopening; unrelated data is never replaced.

IngressBudget's existing reserve-before-copy mechanism now accepts an explicit
private capacity; its no-option S2 behavior is unchanged. Store snapshots charge
the canonical header/frame/row copies before allocation, keep the reservation
until actual settlement and bound pending calls to 64. Complete generated batches
are checked again, including physical encoded bytes, before native publication.
The 64 MiB logical admission budget is not a native RSS guarantee (study is t16).

On mutation rejection, timeout, lost reply or publication mismatch the writer
fences further work. A caller timeout does not resolve the writer lane: native
promise, pending reservation and ownership stay live. After actual settlement,
fresh reads compare every outgoing row and table version against the captured
old state or complete batch. Only verified old/complete settlement permits close;
writer admission remains fenced until close/reopen. An unverifiable outcome keeps
pending nonzero and fails cleanup while the OS owner remains held.
