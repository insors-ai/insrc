# S3 task 7 — authoritative queue receipt adapter

Implemented the unchanged S2 ReceiptVerifier contract over immutable native
ReceiptPayload rows. Identity and operation lookups use validated internal hashes;
returned proofs contain only queue identity/scope/epoch/hash/generation and the
minimal operation receipt. Native handles and domain text never escape. Requested
visibility is enforced; QueueAdmission's current-binding epoch checks remain intact.

Proof reads share AtomicWriter's ordered lane and admission accounting. They remain
available after mutation stop, so queue ACK/retirement can finish before store
close. A fenced unverified native outcome or a closed facade is unavailable, not
absent. Root/profile validation and receipt-count/generation coherence precede
absence as well as found results. The writer uses the same root coherence check.
Duplicate/malformed authority is unavailable and cannot authorize retry mutation.

confirmRetirement validates exact operation, generation, identity/payload hashes,
canonical scope digest and epoch digest, returning only a boolean for a valid
lookup. Authority failures throw a fixed STORE_UNAVAILABLE error. S2 readReceipt
continues to convert that into its existing non-fencing ReceiptUnavailableError;
no S2 wire/frame/proof shape or retained-frame matcher was changed.

Node 22.23.2/APFS: 21 relevant native tests pass, zero skips (`t7-tests.tap`): four
real store/queue adapter cases, eight writer cases, three S2 receipt contract cases
and six retirement regression cases. The existing retained conflicting-authority
test still covers pending and terminal frames with both payload and scope changes.
Standalone build and root typecheck pass. Initial receipt assertions were corrected
to compare canonical wire values: S2 intentionally returns null-prototype snapshots.

Real adapter tests verify accepted -> committed with queue still pending, explicit
ACK, actual segment recycling, unchanged replay identity, cold native+queue reopen,
retirement digest mismatches, minimal projection, scope/epoch isolation, mutation
stop with proof reads still available, closed-facade unavailability and deliberate
duplicate/malformed/missing native proof/root injections. Failed lookups/ACKs keep
the queue checkpoint unchanged and usable, and corrupt authority permits no replay
mutation. The store never calls queue.markResolved or any queue callback.

These are focused adapter checks, not the process-crash qualification gate: t10
still requires actual queue/store SIGKILL boundaries on APFS and ext4. Broad forget,
read leases, full two-participant OwnedWork integration and production host wiring
remain t8 onward. No runtime/model configuration changes or full sweep.
