# S3 task 9 — bounded coherent pinned reads

Implemented private ReadLeases and NativePinnedReader. Each registered opaque
snapshot owns a distinct table handle pinned to a captured native version/root
generation. Copying a snapshot or using it with another owner/scope grants no
authority. Current projection consumes the lease and closes its handle; explicit
release is idempotent. Production defaults are 16 leases and 30 s monotonic lifetime.
Idle expiry closes immediately; an active read is discarded and closes only after
its owned work settles. Private fault hooks do not add public MemoryOptions fields.

Private store opening accepts the existing host binding port for reads; a missing
port fails NOT_READY rather than inventing project/epoch authority. Binding calls
run outside the writer lane. Final double collection checks the unique host binding
and monotone store head for a coherent overlap, followed by validity/lease checks.
The trusted host must never reuse an epoch after rebinding. Concurrent forget,
generation, binding or time eligibility changes discard the projection.

Scope predicates enumerate at most eight qualified namespace hashes; raw project,
branch, environment, session and epoch strings never enter SQL. Native queries
enumerate bounded IDs before loading payloads. Native octet_length checks precede
payload transfer; canonical copy accounting bounds JS-owned read work. Scalar
projections omit unused vectors while preserving verified schema/profile metadata.
Complete current/revision/receipt/evidence/source links, authority, exact and broad
tombstones, source lifecycle and validity are checked before views/eligible row IDs
are returned. Work/result/byte overflow fails explicitly, never truncates an ANN
result. No ranking or public semantic read is implemented (S5 owns those).

Private currentProjection supplies eligible physical row IDs in item order and the
earliest future/current/source validity boundary for S5 query/cache integration.
prepareEmbeddingQuery validates the same store model/dimension/preprocessing profile
against a registered lease; text remains verbatim and floats convert once without
renormalization. No model calls or re-embedding.

Startup now validates every physical row against its scalar columns before trusting
the audited version, not just receipts. Otherwise a corrupt current status could
hide content, or a corrupt tombstone namespace could hide protection before a
targeted decode. Payloads are fetched individually after native size checks; metadata
is streamed. Hot unregistered native mutations remain refused by the t7 version guard.

Verification: Node 22.23.2/APFS, 42 focused tests pass, zero skips (`t9-tests.tap`);
root typecheck and package build pass. Eleven reader cases cover real scalar and
mixed-null-vector data, distinct pinned handles, cross-instance/scope/copy refusal,
SQL-like qualifiers, scope subsets, cold reopen, generation/forget/binding races,
source expiry without commits, future validity/cache boundary, lease limit/release/
idle expiry/active monotonic deadline, exact query profile/text/Float32 behavior,
and cold filter-column corruption. A separate pure manager/port case proves result,
protection-reference and byte overflow before candidate payload loading. It is not
represented as a native cardinality or process-crash qualification.

## Validation correction — asynchronous cleanup after freshness check

The first verdict (`t9-gate-first.json`) found a real stale-return window: final
checks ran before awaiting reader.close. The read-close hook could wait while a
forget, binding or expiry completed, then the old projection would return.

Reader cleanup now completes before final binding/generation/time checks. The
success path has no await in its finally block after those checks. An active
facade operation remains counted after its native handle closes, until final
validation/return settles, so that cleanup ordering does not report false pending
zero. Activity tracking observes the original promise without delaying its return.

Added a native read-close barrier test with four cases: forget, rebinding, source
validity expiry and monotonic lease expiry while cleanup waits. Each rejects the
old projection, verifies pending work stays nonzero during cleanup and ends at
zero after settlement. All 12 reader tests pass, zero skips, in about 6 s
(`t9-retry-tests.tap`); package build passes. This rerun is the affected reader
scope, not a full package/backend sweep. No timeout/configuration changes.
