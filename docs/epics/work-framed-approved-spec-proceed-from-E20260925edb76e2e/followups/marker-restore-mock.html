Restored markers keep their glyph & tone

In a live turn, lifecycle markers already render as terminal status lines with their phosphor colour (shipped in S004). But when a chat is restored from history, every marker row currently replays as plain text — indistinguishable from what the assistant said. This follow-up persists a marker's style so a reloaded transcript reads exactly like the live one.

why

The transcript row (TranscriptEntry, sc4) stores only role + text. On restore the webview draws each row with line(x.text) and no CSS class, so the sc1 glyph and colour are lost. The fix adds an optional cssClass to the stored row.

What changes (sc4)

  • Add optional cssClass to TranscriptEntry — set when a marker row is written.
  • Restore replay draws marker rows with line(x.text, x.cssClass) instead of bare text.
  • Older stored rows (no cssClass) still restore as plain text — no migration, no break.

Stays the same

  • One nonce'd inline script + strict CSP; labels via textContent (no innerHTML).
  • Live rendering (S004) is untouched — this only enriches the restore path.
