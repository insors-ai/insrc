**Where the build departs from the approved design.** Each was reported to the
build gate. A reader of the LLD should know them:

1. `renderMeasureLine` lives in `src/analyze/completeness.ts`, not in

   store modules. The move is harmless and was left.
2. The planner stamps the plan's size from the intent (`src/analyze/planner/driver.ts`).
   Before, the task band was read for the size the model wrote in its own plan.
3. The measure taken from lookup results never throws. A malformed output is
   named in the measure's note.
4. `prepareAnswerTurn`, `concludeRun` and `completeRun` take an optional measure.
5. The daemon's intent parser takes the size as required or optional per request.
6. Test seams: `_setMeasureDepsForTest`, `_setClassifyForTest` (plan tree's
   driver), `_setClassifierForTest` (daemon), `oneShotRunParams` (MCP server),
   `_groundingIntentForTest` (workflow runner).

## 5. Found and neither fixed nor filed

Each of these is known and has no record on the ledger. Decide for each whether
to file it.

1. **The build keeps compiled files whose source is gone.** Both `out/` of this
   repository and `~/.insrc/daemon/out/` still hold
   `analyze/classifier/scope-picker.*` and
   `prompts/analyze/scope-picker.system.md`. Nothing imports or reads them.
2. **This repository's `out/` is in the index.** The whole-repository live
   run's context named `out/prompts/analyze/scope-picker.system.md` as a file
   of the repository. `out/` is ignored by git and still indexed, so an
   analysis can cite build output, including stale build output.
3. **The index held a file that is no longer on disk.** A lookup of the live
   run skipped `vscode-plugin/src/chat/__tests__/chat-view-channel.test.ts`
   for that reason. The lookup reported it; the stale entry itself was not
   looked into.
4. **A request that cannot be counted announces XL before it is refused**
   (code review, finding 12, low). The `classified` event carries `size: XL`
   with `determined: false` and the scope check refuses the request only
   afterwards. Anything keyed on "L or XL" (the token warning the framework
   design describes) would announce a large run for a request that is merely
   unindexed. A consumer should read `measure.determined`.
5. **Code review finding 10 (low), not fixed.** `measureReposUnder` repeats the
   counting loop that `measureNamedArea` has.
6. **Code review finding 11 (low), not fixed.** `underRoot` in
   `src/analyze/explore/types.ts` treats a path as absolute only when it starts
   with `/`. Harmless on the supported platforms.
7. **The plan request's depth rule at depth 0 is asserted on a function, not
   through a request.** No request can exceed a depth cap at depth 0, so
   `planDepthScope` is tested directly.
8. **The daemon suite can hang when two test runs overlap.** It hung once in
   `src/daemon/__tests__/model-catalog.test.ts` and twice in
   `src/daemon/tools/builtins/code/__tests__/migration-walk.test.ts`. Each time
   another run, or the children of a run that had timed out, was still going.
   Both files pass alone and the suite passes run alone. Whether there is a
   real sensitivity under it was not investigated.
9. **An orphan test process is still running.** Pid 15309, started 2026-10-03,
   `src/bin/__tests__/permission-hook-integration.test.ts`, with no parent. It
   does not hold the graph store. This session did not start it and left it.
   (`src/bin/permission-hook.ts` does not exist; the test came over without
   its implementation.)
10. **`src/shared/classify.ts` is an unused classifier type with its own size
    scale and a "defaults to M" comment.** It is not the analyzer's and nothing
    imports it. Left as it is.
11. **`vscode-plugin/package-lock.json` has a stale `version` field (0.4.8).**
    Carried from the earlier handover; still so.
12. **The JetBrains plugin was not checked against the removed role.** It reads
    its settings from the daemon's catalog, so the role should simply
    disappear from it. That was not opened and looked at.

## 10. Working notes for the next session

- **A workflow's state token does not survive the end of a turn.** Run a whole
  `design.story`, `plan`, `issue` or code review in one turn, and ask the
  stakeholder's decisions before starting it.
- **The build gate's `validate` needs the `tests` mapping**: each planned
  test's exact text, mapped to a file and a test title. For a live or smoke
  test, give `reported` with the result and where the evidence is.
- **One named test can span two tasks.** t6's first test covered t7's surface,
  so the two were built in one commit and sent through the gate in turn.
- **Run suites one at a time, and kill a timed-out run's children before
  starting another.** Compare by test name against a baseline; `tsc` does not
  compile the tests. Use Node 22 (`/opt/homebrew/opt/node@22/bin`).
- **A whole run can be driven with no model** in a test:
  `registerBuiltinTemplates()`, `registerBuiltinRuntimes()`, and a routing
  stand-in whose model returns a plan for the role `analyze.plan` and the
  smallest value the schema accepts otherwise. See
  `src/analyze/orchestrator/__tests__/run-measure.test.ts`.
- **Do not let a unit test reach the classifier's own context build.** It is a
  tool loop on the local Ollama model; it hangs for minutes and really calls
  the model. Use the classifier seams.
- **Read a failing task's own record before naming a cause.** This session
  first blamed the shared task files for the missing child reports; the
  child's record said "Prompt is too long".
- **Live runs spend the stakeholder's Claude quota.** One at a time, detached,
  only on the stakeholder's word, after checking that no other session is
  running one. The client used is `S002/measurements/live/run.mjs`.
- **Daemon update:** `maintenance.update({}, log)` then
  `maintenance.restart(log)` from `~/.insrc/daemon/out/cli/services/maintenance.js`.
  A running session's MCP server keeps the code it started with until reloaded.
- **Extension release:** `npm run package` in `vscode-plugin`, install with
  `"/Applications/Visual Studio Code.app/Contents/Resources/app/bin/code" --install-extension <vsix> --force`
  (`code` is not on PATH), publish with `vsce publish --packagePath <vsix>`
  (the publisher `insors` is logged in). The listing takes several minutes to
  show a new version.
- **Upstream moves during a session.** Merge with `git merge --no-ff` as its
  own commit before a push; never rebase or squash.
