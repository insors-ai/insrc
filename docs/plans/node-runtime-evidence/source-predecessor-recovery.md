# Historical predecessor inventory and recovery (task t3)

Scope: ISSUE/LLD/PLAN `a03e99e17a364550`, story s1, task t3. This is preparation and admission evidence. Linux cutover, public installer/client routing, and production historical/native upgrade qualification remain tasks t4–t12. No user daemon or live database was changed.

`inspectSourcePredecessor` records the current source HEAD/dirt separately from measured executable, dependency and runtime bytes. It reads install markers and compiler attestations as diagnostics; neither editable metadata nor Git HEAD proves what produced `out`. An independently retained installation-owner pin, or an authenticated catalog fingerprint matching the actual bytes, is required to admit an existing rollback baseline. Unknown output, incomplete dependencies, dirty source/lockfiles and stale source/output block normal admission. A caller holding a process capability can also inventory the actual live executable/cwd without sending signals; preparation never confers process-stop/start authority.

`prepareSourcePredecessor` returns `existing-qualified`, `rebuild-staged`, or `recovery-required`. Recovery is explicit, never automatic. A signed compatibility entry alone does not authorize old source execution: the predecessor entry must additionally contain `recovery: {tree: <exact Git tree>}`. The independent verifier authenticates the current release channel/tag/sequence, exact predecessor commit/tree and launch profile before checking out old code. It retains current source floors while rebuilding the historical predecessor, rather than rolling authorization back to an older tag.

| Relationship | Direction / ownership / cardinality / compatibility |
| --- | --- |
| Signed target catalog → predecessor declaration | Candidate owns zero or more exact prior-commit entries. Each entry authorizes one compatibility pair and its allowed launch profiles; existing compatibility-only entries retain normal behavior. |
| Predecessor entry → optional recovery tree | Zero or one exact tree per prior commit; explicit permission to independently rebuild that commit, not permission to start it against user data. |
| External authenticated bootstrap → staged historical checkout | Bootstrap owns runtime provisioning, native smoke and binding helpers; the historical checkout remains separate from the incumbent and need not contain modern bootstrap assets. One resulting baseline pin records its actual newly built bytes/runtime. |
| Preparation result → lifecycle transaction owner | One qualified baseline and old/new compatibility pair are handed to the platform owner. Original-process closure, quiesced-store compatibility, durable selection and readiness/rollback remain mandatory before activation. |

`out/bin/insrc-source-recovery.js` is an internal independent-package helper, not a TUI subcommand. `inspect STATE_ROOT INSTALLATION_ROOT INCUMBENT_RUNTIME` is read-only. `prepare REQUEST_JSON --rebuild-predecessor` requires an owned private bounded JSON file with string fields `stateRoot`, `installationRoot`, `incumbentRuntime`, `verifier`, `repoUrl`, `branch`, `priorCommit`, `launchProfile`, and optional `target`. The bootstrap package must be outside the incumbent checkout. Both commands explicitly report `activationPermitted: false`; structured recovery guidance includes prerequisites and a separate-empty-home route. Delivering that current authenticated package and wiring installer commands is t5; no claim is made that an old installation already ships this helper. Never run a staged daemon directly against retained user state.
