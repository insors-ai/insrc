## Summary

No security hole. Exact consent binding, read-only detection, no-elevation and archive extraction are sound. The blocking issues are about **recovery**: the code correctly refuses to guess when evidence is uncertain, but it has no path to retire evidence left by a dead actor. Ordinary events (closing a terminal, a kill, an upgrade) can leave an installation wedged until private files are deleted by hand. Findings 1–4 share that root cause and should be settled in one "dispose of dead-actor evidence" design pass. Two further blocking items concern the evidence and one test.

## Verified sound

- **Exact consent:** offer id = SHA-256 over policy hash, installation id/home, target, destination, endpoint, models/logs dirs, `start` and the observed absence (incl. search-path digest); re-checked against the manager's locked inspection, inside `decide`, and by prepare/service rechecks. Changes → `dependency-offer-stale`; no silent widening; stored `installOllama` intent rejected.
- **Capability:** frozen WeakMap-registered context bound to installation id/home; `assertCurrent` re-checks lease, cancellation and phase; adapter never sees ControllerStore.
- **Read-only detection:** lstat/stat/access/readdir, bounded O_NOFOLLOW reads, loopback-only `GET /api/version`; redirects/non-200/oversized/malformed/timeouts → `unavailable`, never `missing`.
- **Advisory agents / no elevation:** presence-only CLI detection, never a blocker; no sudo, PATH or global-config writes; sanitised explicit child env, argv-only launch.
- **Production composition:** only the real dependency adapter added; lifecycle/migrations stay absent; terminal-install fails `capability-unavailable` before inspection.
- **Archive handling:** digest + size verified before extraction (`download.ts:54-61`); strict single-frame zstd with window/output bounds, XXH64 and cross-check against Node's decoder; strict tar headers, whitelisted PAX, rejection of device/FIFO/sparse, traversal/ADS/reserved names, NFC/case collisions, linked ancestors; ZIP envelope with single EOCD, consistent ZIP64, contiguous members, CD/local agreement, raw-vs-decoded names; aliases bound to policy, no links in final tree; fsync + exclusive no-replace rename; close errors → `resource-close-uncertain`. Decoder deps pinned (`fzstd` 0.1.1, `xxhash-wasm` 1.1.0) with integrity and bundle allow-list.
- **Service lifecycle:** frame + admission durable before spawn; pre-admission cancel starts nothing; post-admission cancel retains service; no `kill()`/PID use; duplicate start prevented by installation lock, `record.lock`, `service.lock` and launch-fact check; foreign listener recorded as `endpointOwnership: 'unproven'`; supervisor `setsid` + `unref`, O_CLOEXEC locks; `safe_path` (C) correct on free/`LocalFree`, rejects reparse points, NULL DACLs, foreign allow ACEs.
- **Evidence:** `shasum -c SHA256SUMS` 488/488 OK; 34 per-file TAP logs sum to 152/152 pass, 0 skipped; 43/43/43 admissions/results/disposals with identical child-id sets, all exit 0, all disposals `closed`; `git diff 8e2534b4 01d08cad` over BUILD_INPUTS is empty; raw native files agree with `qualification.json` (policy hash, asset, Ollama 0.40.18, Node 22.22.1, 49 files, zero models, 36 ms / 39,507 rchar); only linux/arm64 in the catalog, five routes pending with reasons; superseded 152-pass run correctly excluded.
