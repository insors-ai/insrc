Linked scratchpads in VS Code

A developer can record an investigation, connect it to the code and workflow records it concerns, and recover that reasoning from either direction. Selected scratchpad evidence can accompany an agent turn or seed a workflow draft.

Problem and scope

Today a scratchpad is easy to find when it is recent. A developer returning to a design or symbol later has no comparable way to find the scratchpads that explain it. Pasting text into chat also loses the connection to the originating note and its supporting references.

Primary journey. In VS Code, a developer writes a retry-policy investigation and links a related scratchpad, the queue symbol, and its LLD. A later visit to the LLD or the symbol reveals that investigation. The developer finds a discarded option by searching the note body, sends an excerpt and selected evidence to the current agent, and uses the conclusion to seed a workflow draft when ready.

  • P0 covers explicit repository-scoped links, backlinks, search in the open note and across saved notes, dated entries within each scratchpad, and basic note lifecycle in the supported VS Code extension. Existing in-plugin Markdown editing work is a dependency.
  • P1 adds cited agent context and explicit promotion to a workflow draft. Tags and starter templates can follow the link and lifecycle work.
  • Out of scope includes vault import and sync, shared note editing, a general-purpose canvas or graph browser, unlinked mention suggestions, arbitrary transclusion, automatic project-memory ingestion, and new client surfaces for the CLI or JetBrains. Semantic scratchpad search and ephemeral analyzer-output links are candidates for later work.

Product requirements

SP-1 · P0 · Author and resolve links

Open a pad in VS Code’s built-in Markdown Editor (vscode.markdown.editor) on its real file, rendered in place with inline click-to-edit rather than a bespoke editor or a raw source view. From there, developers can type an Obsidian-style [[…]] link or insert one through a target picker. The picker searches notes, repository files and indexed symbols, and readable workflow records such as a SPEC, ISSUE, HLD, LLD, or TASK. The rendered link shows a readable label and opens the exact target in the current scratchpad, editor, or artifact view. The picker commits a qualified target so duplicate titles and symbol names are safe. Ambiguous, unavailable, and missing targets are distinguishable and repairable. Treat example links in Markdown code spans and blocks as literal content.

SP-2 · P0 · Discover backlinks

Show outgoing links and incoming scratchpad backlinks in the note view. On an active file or chosen symbol, expose a VS Code “Show scratchpad backlinks” action. Show a matching section on the workflow artifact detail surface. Each inbound result names the note, shows a matching line or excerpt and its archived status where applicable, and opens the originating occurrence. Group repeated occurrences by source note and derive both views from the same directed relationship. Explicit note references have their own presentation alongside existing graph evidence.

SP-3 · P0 · Find in a note and search across notes

Find in note is a separate, in-pad search: the find bar and match highlighting operate on the open scratchpad only (see the mock). Provide an editor-local search action with Ctrl/Cmd+F when the scratchpad editor has focus. Search the current text, including unsaved edits and entries under collapsed dates. Highlight matches, show the active match and total count, and move to the previous or next match with wraparound. Reveal the active match by opening its date section when needed. Enter and Shift+Enter navigate. Escape closes Find without changing the document. A zero-match query shows an explicit empty state.

Search all notes. The search textbox lives at the top of the “insrc scratchpads” list panel — the page the chat panel’s list-scratchpads button opens — not in a separate navigation-panel view and not inside the open pad (with several panels open, an in-pane search section would take too much space). That panel lists up to twenty scratchpads ordered by recency with each pad’s first three lines; typing in the textbox filters this list by relevance over saved titles and full Markdown bodies within the supported note size, and clearing the query restores the unfiltered recency list. Title matches rank ahead of body-only matches; ties order by modification time and stable identity. Clicking a filtered or unfiltered pad opens it in VS Code’s built-in Markdown Editor. Lexical search works without a model or embeddings. The active repository is queried by default, with a separate local, unassigned view for legacy and workspace-free notes, a linked-target filter, and an include-archived toggle.

SP-4 · P0 · Preserve scratchpad identity, dated entries, and lifecycle

Keep the existing Markdown files readable. Assign stable identity when a note joins the enhanced store and preserve it across title changes, supported moves, archive and restore. Existing notes remain visible and editable through the local view, and users explicitly associate an existing note with a registered repository. A note created for a clearly identified repository gets that scope up front. Support rename, reversible archive, and restore. Archived notes are hidden from recent, default search and default backlinks, and a direct link can still open the archived source. The existing delete flow remains available with an explicit permanent-delete decision. Permanent deletion removes the note from search and backlinks and renders surviving incoming links to it as missing.

Dated entries. A scratchpad can hold multiple Markdown entries. Provide a way to start a new entry in the open scratchpad. Record its creation timestamp on the first successful save and show its time under the corresponding local calendar date. Inside that scratchpad, list days newest first and entries newest first within a day, with a stable tie-breaker. Each date section has an entry count and expands or collapses independently using a keyboard-operable control. Editing or moving an entry within the scratchpad preserves its creation timestamp. Existing Markdown without entry timestamps remains readable and appears under Undated until the user supplies a date. The scratchpad’s filename timestamp describes the file and cannot establish dates for its entries.

Editing surface. Open a pad in VS Code’s built-in Markdown Editor custom editor (vscode.markdown.editor, shipped in the markdown-language-features built-in extension) on the scratchpad’s own file, in place of today’s read-only custom webview. The editor renders Markdown directly and supports inline click-to-edit on any block via its floating edit affordance, a lock toggle for a read-only view, paste/drop of an image into the note (markdown.editor.filePaste.enabled / drop.enabled, materialized into the workspace), pasting a URL as a formatted link, and the built-in insert-link/insert-image-from-workspace commands — all operating on the same file our save path already writes, so Ctrl/Cmd+S and external reconciliation are unchanged. Use the tracked editing work as the save path. Save and metadata changes must preserve the prior committed version on failure. A stale editor or another VS Code window must surface a conflict with the newer saved revision and retain the unsaved draft. Temporary writes are excluded from indexing. Supported external edits and deletions are picked up on reconciliation.

SP-5 · P1 · Attach cited context to an agent turn

Keep existing Send to chat for text insertion. Add a distinct action to attach a saved note or selected excerpt to the active turn. Show a removable preview with source, saved revision, and any linked targets whose excerpts the user selects. At submission, adapt a bounded payload to the current controller or to a daemon analysis request where that workflow accepts context. Carry the scope, note ID and revision, source range, and readable citations. Flag unsupported routes, stale or missing sources, and omitted content in the preview or send flow. Queued turns must preserve the approved revision or ask the user to review the replacement before dispatch.

Treat note text as user-selected evidence with draft or archived status. Normal provider routing, intent, and tool permissions continue to apply. Restrict each submission to the currently approved excerpts. Carrying evidence into another turn or workflow requires a new selection, and linked excerpts always require individual selection. If the approved excerpt entered a transcript or artifact, subsequent note edits or deletion leave that historical snapshot intact.

SP-6 · P1 · Promote a conclusion into a workflow draft

Let the user choose a saved selection, review it, select an existing workflow entry point, and seed a draft through the established flow. The first supported destinations are a SPEC via brainstorm or an ISSUE for a defect. Direct links to existing HLDs and LLDs work in P0. A successful promotion adds an ordinary outgoing link to the resulting workflow record and a visible provenance entry on the note. Use the note ID and revision in provenance where the target's visibility permits it. For shareable artifacts, preview the exported text and omit private local paths and inaccessible backlinks. The workflow retains its existing review, approval, and write rules. Cancelling or failing the draft must leave the note usable without a false promotion record. Retrying the same operation after a lost response should recover the existing result without creating a duplicate draft.

SP-7 · P1 · Organize and start related notes

Offer optional tags with a Browse all filter and a small set of templates for investigations and decision candidates. A template populates normal editable Markdown. Scratchpad metadata and headings preserve the existing workflow's ownership of official decisions and approvals.

Interactive mockups

The first window is the “insrc scratchpads” list panel opened from the chat panel’s list-scratchpads button: a search textbox on top and up to twenty pads newest first, each with its first three lines and a delete button. Typing filters the list by relevance (title hits rank ahead, matches highlighted in the previews); clearing restores the recency list. Clicking any pad opens it in the second window — VS Code’s built-in Markdown Editor on that pad, rendered in place rather than as raw source. It opens locked (🔒); click the pencil to edit inline, click the lock to return to the rendered, read-only view. Find in note moves through matches, including matches in collapsed date sections, independently of that lock state. Expand a date inside Queue retry policy to see its entries, and use the ‹ button to return to the list.

Integration and identity

Scope and ownership. Keep notes local to the user. Keep Markdown authoritative for note text and explicit authored links. Store stable scratchpad ID, scope, title, and archive state in durable local note metadata. Give dated entries stable anchors and persist their creation timestamps with the scratchpad so search locations and dated sections can be rebuilt from saved content. The encoding must keep standard Markdown readable. Derived search and backlink records can be rebuilt from the saved files and metadata. Use the registered root associated with the active VS Code resource. In multi-root windows without an unambiguous active root, ask the user which repository to use. Validate scope before lookup or context assembly. P0 link discovery stays within that repository and its active checkout. Unassigned notes can be read and searched in their local view and only become eligible for graph joins and linked agent context after explicit association.

Reference contract. One note owns zero or more directed authored references. A target has zero or more incoming references, with one presentation row per source note and one or more source occurrences. Keep a source revision and current locations for those occurrences. A linkable target has the following logical address.

Graph and indexing boundary. Reuse existing path and symbol resolution, artifact readers, evidence labels, and inbound/outbound query patterns. Start with a private, repository-keyed scratchpad index that joins by validated target identity. Compatible storage can be selected in design. The home store stays outside repository enrollment and default document search. Scratchpad references are distinct from code dependency edges and model-suggested relations. Keep database access in the daemon and serve the VS Code extension through typed IPC. The host can continue local file actions if daemon-based resolution is unavailable and must show that status without fabricating results. Repository and IPC contracts · Repository watcher

Consistency and rendering. Reindex only affected notes on save, archive, restore, scope change and delete. Revalidate affected endpoints when the registered checkout changes or an artifact becomes unavailable. Reconcile from disk on startup, after missed events, and after index rebuild. Guard path containment and refuse symlink escapes on read and write. Treat note text and link labels as untrusted content, preserve webview isolation, and route navigation through the host's validated handlers. Use bounded and paginated searches and follow the existing provider and connection-execution constraints. Local file validation · Host navigation · IPC execution classification

Scratchpads operate independently of the proposed shared project-memory system. Promotion creates evidence for a chosen workflow record. Any future project-memory ingestion must make its own capture and review decisions. Shared project memory requirements

Acceptance and rollout

Land the separately tracked save path first. Deliver SP-1 through SP-4 together so a new link works through both the note and its target surface. Add SP-5 and SP-6 after reference identity and lifecycle pass the VS Code integration checks. SP-7 can ship independently after the metadata contract is in place.

During the pilot, measure time to reopen an investigation from its target, search latency, save-to-backlink visibility, and the frequency of broken or ambiguous links. Prove the model-independent paths with model services disabled. Record the note corpus size and machine configuration before setting latency targets.

Open implementation decisions

  • Choose user-readable Markdown syntax for qualified targets, versioning and alias escaping. Decide how within-scratchpad entry boundaries, timestamps and stable anchors are encoded, and where scratchpad metadata lives.
  • Select the private backlink projection and lexical index. Establish supported note size, update visibility and search latency targets from representative corpora. Determine the minimum daemon version and extension version negotiation for new IPC.
  • Choose the first controller and daemon context routes, evidence budgets and the preview behavior for targets that change during a queued turn. Confirm the SPEC and ISSUE draft entry points can carry the selected evidence under their existing ownership and approval rules.
