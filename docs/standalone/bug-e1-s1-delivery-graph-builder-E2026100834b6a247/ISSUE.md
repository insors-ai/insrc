# Raise a record-unreadable notice for every store file the loader could not read

## Reproduction

Put one malformed file (for example invalid JSON in .insrc/artifacts/LLD-<hash>-s2.json) among valid records, load the store with loadArtifactRecordSet and build the graph with buildWorkItemGraph. Observed: the record set lists the file under failures, but the graph's notices contain no 'record-unreadable' notice, so nothing in the delivery view says the file could not be read. Expected, per the approved s1 design: one store-level 'record-unreadable' notice per load failure, naming the file in fileNames, with attention true.

## Root cause

buildWorkItemGraph (src/workflow/delivery/graph.ts) reads only recordSet.records; it never reads recordSet.failures, and none of its makeNotice calls uses the 'record-unreadable' code (it raises only identity-anchor-missing, identity-ambiguous, unresolved-parent and unattached-spec). The code and its attention value exist in types.ts and notice.ts, and the approved s1 LLD assigns raising it to the graph builder, but the build left it out.

## Fix intent

The graph builder reports every load failure in the record set as one store-level 'record-unreadable' notice that names the failed file (fileNames) and carries the failure reason and detail, with attention taken from the fixed table (true). Nothing else about the graph changes: no items are added or removed, and other notices are unchanged.
