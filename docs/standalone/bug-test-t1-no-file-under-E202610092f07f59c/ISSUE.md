# Bound the S004 src/-untouched guard test to that Story's own build window

## Reproduction

Run `cd vscode-plugin && npx tsx --test src/chat/__tests__/docs-review-panel.test.ts`. Observed: the test 't1: NO file under src/ is modified — the fact that makes S004 need no daemon rebuild' (docs-review-panel.test.ts:4004) fails. Its `assert.deepEqual(daemonFiles, [], …)` at :4037 lists every src/ file changed since 87f3f2f3, 442 files at 9af198ab, including src/agent/providers/cli-provider.ts and src/workflow/delivery/types.ts. Expected: it passes. The Story it guards (Epic build-vs-code-plugin-ui-integration-E20260929bfe98ff7, S004) touched no src/ file in its own commits: `git diff --name-only 87f3f2f3..5db5fe95` lists 0 src/ files and 4 vscode-plugin/src/chat/ files (docs-review-panel.ts, protocol.ts, __tests__/docs-review-panel.test.ts, __tests__/fixtures/ux-parity.ts). Consequence: the file's suite is red for any later build that validates it. The build validation gate refused E2 s4/t3 twice for this test alone (verdict passed:false, check 'The pane's existing tests pass unchanged').

## Root cause

The test computes its window as `git diff --name-only <planCommit>..HEAD` (:4024), where planCommit is the last commit touching docs/epics/build-vs-code-plugin-ui-integration-E20260929bfe98ff7/S004/PLAN.md (:4020, resolving to 87f3f2f3 'S004 PLAN approved'). It unions that with `git status --porcelain` (:4027) into `paths`, and asserts that the src/-prefixed entries of `paths` are [] (:4036-4037). Both ends of the window are open: HEAD and the working tree keep moving after the Story closed, so the window grew to cover every later commit and uncommitted change in the repo. The window was correct only while S004 was in progress. Once its BUILD was approved (5db5fe95, the last commit touching S004/BUILD.md; 87f3f2f3 is its ancestor), the guard began checking other work's src/ changes against S004's rule. The same open window is used by a second test from that Story, 't6: docs-sections.ts is BYTE-IDENTICAL' (:5640-5650, `${planCommit}..HEAD` at :5648). It passes today only because no later commit has touched docs-sections.ts.

## Fix intent

Close the window at the Story's own completion point in both tests that use it (:4004 and :5640). The end becomes the commit that approved S004's BUILD, recorded in the repo as the last commit touching its S004/BUILD.md, in place of HEAD (and, for :4004, the working tree). Each guard then checks exactly S004's committed change set. The existing assertions stay: the PLAN commit is a commit, the window is non-empty, nothing in it is under src/, and the Story worked in vscode-plugin/src/chat/ (for :4004); docs-sections.ts is not in it (for :5640). The change touches only this one test file; no production code changes.
