# T3 — bounded official runtime staging

Registered admission: `TASK-446ae69566d352dd-s1-t3`, after T1/T2 passed their
registered validation. Staging does not publish a runtime/release, select an
installation or invoke daemon lifecycle.

`src/installer/runtime-acquire.ts` downloads only pinned official assets under
the original live owner and a private unique work directory. It reuses the
existing bounded HTTPS/status/redirect/size/hash checks, waits for completion
on cancellation, and bounds an unresponsive actor's abort drain to five seconds.
Uncertain closure retains the stage and reports `resource-close-uncertain`.
Only a same-process stage proof can be discarded by its original live owner;
T4 will consume that proof for publication.

`src/installer/runtime-archive.ts` authenticates exact parser-input bytes and
extracts the fixed Node/npm/header/library profile. It reuses the tar
header/PAX/byte primitives factored from the S3 reader, existing file-close
primitives, and the T2 independent inventory verifier. Gzip decoding has a fixed
output cap and is awaited before cleanup. ZIP input is an authenticated bounded
RAM buffer; its entry streams are explicitly closed. No target code executes.
Stages receive canonical inventory/completion only after matching the separate
release-owned inventory pin. Metadata and payload writes are positively closed.

The first run exposed a mistaken wait for `ZipFile.close` on a `fromBuffer`
reader. Yauzl3.4.0 documents that this in-memory reader never emits that event
and owns no fd. The implementation now waits on actual entry decoder streams
and stops further ZIP admission, without claiming a nonexistent fd-close proof.
The failed/cancelled test result is retained in run
`6837a11d-2ac6-4ce1-a21b-daf752c6fc23`; it is not counted as successful evidence.
