# T4 — controller-owned immutable runtime publication

Registered admission: `TASK-446ae69566d352dd-s1-t4`, after T1–T3 passed.

`ControllerStore.publishRuntime` retains the original private native handle.
Only a same-process stage branded for that exact owner is accepted. Before
publication it rechecks the work root identity, verifies all staged content
against the independent policy, flushes directories, and rechecks live ownership.
The existing native `publishDirectory` performs exclusive no-replace publication
(macOS RENAME_EXCL, Linux RENAME_NOREPLACE, Windows WRITE_THROUGH without replace).
Parent namespace flushes follow. The native handle never escapes and no second
controller, lock transfer, manager action or lifecycle implementation is added.

`runtime-install.ts` is an internal acquisition facade within the LLD's shared
runtime foundation component. It snapshots the requested identity, checks for
an existing canonical entry before network, and uses the read-only resolver for
verified reuse. A corrupt/incomplete entry is retained and fails; no repair or
overwrite occurs. Fresh stages are published and only their owned work directory
is discarded; shared runtime entries and application releases are never removed.
`runtime-store.ts` factors the existing content verification into a void-returning
internal staged-content check; arbitrary roots receive no executable paths or
launch authority. Public resolution still requires canonical explicit home and
full identity, and its installer-only import boundary remains intact.

Fresh publication stages contain newly extracted files and never execute Node
or load a native library. The running helper executable and loaded control
library stay outside the moved tree. T5 owns actual terminal child exit and
fresh-lock handoff; this task does not claim those future behaviors.

The bounded actor-drain helper is reused for staged verification/durability.
Unconfirmed verifier closure quarantines the same-process proof and prevents a
later discard, even while the original controller remains held. No automatic
actor-death inference or recovery engine is introduced.
