identity (including baseline and official archive SHA) and independent executable
digest. Fresh inputs are downloaded live with HTTPS/redirect/byte/hash/deadline
bounds before extraction/execution; Windows also gets the separately pinned
headers and matching architecture library. An existing immutable runtime entry
does not trigger download or repair. The script OS-hashes cached Node before
executing it, then the helper uses the shared full read-only resolver/profile.
Matching cached runtime and control files work without curl/tar/gzip or host Node.

longer renames directories or invents ownership. The terminal entry's private
`--bootstrap-publication` branch publishes foundation files only. It does not
invoke a manager install action, enroll/select a release, prompt for dependencies,
transfer a lock, or produce a successful-install claim. `bootstrap-foundation.ts`
uses the original ControllerStore capability and T3/T4 runtime acquisition. Its
local transport reads the script's already downloaded pinned inputs; the same
runtime stage still authenticates the exact parser bytes and independent profile.

`ControllerStore.publishBootstrapControl` copies authenticated buffers into a new
private nonexecuting candidate, closes/fsyncs files, verifies exact membership and
private ancestors back to the explicit home, and uses its retained native handle
for durable no-replace publication. Existing control entries must verify and are
never overwritten. Bounded uncertainty retains the internal stage. The shared
bounded-actor helper now returns a generic result so these paths can reuse it.

The execution Node and loaded control library remain in place. Runtime extraction
and control-buffer copying create distinct publication trees. The helper closes
its controller and self-exits. Only the outer script observing that exact child
exit can launch the canonical control under canonical Node, with ordinary fresh
manager admission. No source/session flag, PID/kill heuristic or native-close
return substitutes for that process boundary. An unconfirmed child exit retains
its outer work stage; only confirmed closure allows cleanup. Terminal I/O and
the final install/TUI invocation remain in the same terminal.

Self-review found and fixed late cancellation during a successful verifier close:
positive close is followed by an abort check, and publication/helper completion
checks abort again before success. The regression case uses a real closed file
handle and confirms canceled reuse cannot be reported as successful.
