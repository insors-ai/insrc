# T6 — application-only bundle format and external publisher runtime

Registered admission: `TASK-446ae69566d352dd-s1-t6`, after T1–T5 passed.

Private release descriptors now use schemaVersion2 without runtimeArchive.
Public ReleaseManifest remains schemaVersion1 with its exact official runtime
identity. Canonical descriptor hashing, durable accepted-offer recovery, installed
receipt reading, ZIP extraction and immutable bundle verification use the new
format together. Embedded descriptor1 is rejected with an explicit diagnostic;
it is neither reinterpreted nor adopted. ZIP bounds, exact inventory membership,
control digests, app entrypoints and native application dependencies remain.

The publisher collects compiled application and actual production/optional/peer
dependency sources independently of its runtime. Canonical source provenance
survives renamed output keys and excludes declared distribution inputs before
inventory hashing. Independent policy digests additionally reject pinned Node
archives/executables, Windows headers/libraries and the enabled Ollama archive
even under renamed destinations. This does not claim to classify arbitrary
unknown compressed bytes. Legitimate .node dependencies, the Ollama JS client
and policy metadata remain permitted. The Ollama asset metadata moved unchanged
to a dependency-free distribution policy module; consent and qualification did
not change.

Publisher probes acquire and resolve a separate private runtime through the
original ControllerStore and the shared verified foundation. They launch the
absolute verified executable with the sanitized runtime environment, with no
PATH, tools/node or arbitrary runtimeDirectory fallback. The real original store
also owns bundle preparation runtime acquisition; its manager lease delegates
that operation without transferring stage ownership to a proxy. Read-only
candidate opening resolves an existing runtime and never acquires one.
