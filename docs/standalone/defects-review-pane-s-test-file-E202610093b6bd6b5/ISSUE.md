# Review pane tests: share one fake DOM, flatten and opener, and skip history- or tsc-dependent checks with a reason

## Reproduction

(4) is the observable failure. Clone the repo shallowly (`git clone --depth 1`), link node_modules, and run `cd vscode-plugin && npx tsx --test src/chat/__tests__/docs-review-panel.test.ts`.

Observed: 197 pass, 3 fail.
- 't3 (contract): docs-sections.ts is unchanged and still has zero imports' (declared at :1483) fails with `Command failed: git show 09e6efa:vscode-plugin/src/chat/docs-sections.ts / fatal: invalid object name '09e6efa'`.
- 't6: docs-sections.ts is BYTE-IDENTICAL' (declared at :3562) fails with `fatal: invalid object name '8908338'`.
- 't1: NO file under src/ is modified' (declared at :4004) fails on its assertion 'there are commits in the build window to inspect' (:4037).

The second test named 't6: docs-sections.ts is BYTE-IDENTICAL' (declared at :5642) passes vacuously. In a shallow clone both ends of its window resolve to the one commit present, so the diff it inspects is empty.

The two tsc probes, typecheckAgainstPanel (declared at :2447) and the never-witness check, assert existsSync(tsc) at :2449 and :2549. They fail rather than skip when the compiler is absent.

Expected: where the history or the compiler a check needs is missing, the check skips with a stated reason, and nothing passes vacuously.

(1) to (3) are not runtime failures today. They are duplication that lets tests drift.
- openWithContent (:961) and openAndGetContent (:606) have the same body line for line. Each builds fakeChannel + fakeClient, creates the host, opens, ticks, sends open-doc for LLD-abc-s7, ticks, and returns that artifact's docs-content payload. The only difference is the client's content: a DocsContent passed through, or { markdown, openQuestions: [], blocked: false } built from a string.
- frAll (:1248), dgFlatten (:2716), allOf (:3306) and uxFlatten (:4161) each return a pre-order list of a tree (node first, then children). dgFlatten does it through an accumulator parameter (n, out = []). uxFlatten skips text nodes. uxAllText (:4168) is a text collector, not a fifth flatten.
- Six fake-DOM element builders have divergent shapes: stubEl (:436), node/StubNode (:705/:715), frNode (:1204/:1215), bodyStub (:1515/:1540), dgNode (:2656/:2667) and uxNodeStub (:4078/:4095). There is also an inert inline document ({ createElement: () => ({}) }) at :5315. Because appendChild, textContent, setAttribute or innerHTML can behave differently between them, a renderer can pass against its own fake while the real DOM behaves differently.

## Root cause

Each Story that added a renderer to docs-review-panel.ts grew its own test scaffolding beside its tests, instead of extending shared scaffolding. That produced six node builders, four flatten helpers and two openers. The fakes encode different, partly conflicting contracts:
- frNode, dgNode and uxNodeStub record every write and trap innerHTML/outerHTML (their trap loops are at :1233, :2682 and :4115).
- bodyStub deliberately parses innerHTML into children, and models insertBefore, parentNode and nextSibling, and querySelector/querySelectorAll.
- dgNode carries an SVG namespace, which tests check at :2860 and :3200.
- uxNodeStub has text nodes (UxTextNode, createTextNode).
- node/StubNode models listeners and scrollIntoView (:705-:727).
- stubEl is a bare record of innerHTML, textContent, className and a querySelectorAll.
So there is no single place where the DOM contract these tests rely on is defined.

For (4), the history checks run git without checking that the history they name exists:
- :1501 and :3567 call execFileSync('git', ['show', '<sha>:<path>']) directly.
- :4023-:4030 use the test's local git(...) helper, which wraps execFileSync, for `git log -1 -- <PLAN.md|BUILD.md>` and then `git diff planCommit..buildCommit`.
- :5648-:5655 make the same log and diff calls through execFileSync directly.
Neither window checks that its ends exist as distinct history. A shallow clone or a source tarball therefore raises a raw subprocess error, or resolves both ends to the same commit and inspects an empty diff. The tsc probes assert that the compiler exists instead of skipping when it is absent.

## Fix intent

- Define once, in one place, the fake DOM that the review pane's renderers are tested against. It keeps every behaviour an existing test asserts on: write recording; the innerHTML/outerHTML trap, and separately the innerHTML-to-children parse, wherever each is relied on; the SVG namespace; text nodes; parent and sibling links; querying; listeners and scrollIntoView. Each suite builds its nodes from that one definition.
- Use one pre-order flatten, which keeps dgFlatten's callers working, and one document opener that takes either markdown or full content.
- Before any check uses git history or tsc, it first establishes that what it needs is there: the named commit, or a real window of distinct commits, or the compiler. When that is missing, it skips with a stated reason, and it never passes vacuously.
- Every existing assertion is kept, and every test still passes in a full clone.
- The fix is expected to be test-only. In a full clone the whole file passes today (200/200), so nothing points at production code. docs-review-panel.ts and docs-sections.ts are not changed.
