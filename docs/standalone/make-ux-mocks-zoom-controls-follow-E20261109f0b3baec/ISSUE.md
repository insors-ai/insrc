# Make UX mocks and zoom controls follow the artifact theme

## Reproduction

Open a generated UX mock companion page, such as `docs/epics/show-long-running-task-progress-chat-E20261109206db342/ux-mock.html`, and switch the page to dark with the theme button.

Observed: the page around the mock turns dark but the mock itself keeps its light colours. The zoom and pan buttons on companion pages do not match the theme. On code diagrams generated by docgen, the zoom controls drawn on the diagram keep fixed black and white colours in both themes.

Expected: the UX mock and every zoom and pan control follow the selected light or dark theme.

## Root cause

Generated pages get their light and dark styling from one shared theme, which every page shell composes. Two parts sit outside it. The UX mock's card styles are written with fixed light-mode colours instead of the theme's colour variables, so switching theme has no effect on them. For the zoom and pan controls there are two separate causes: the companion page puts its buttons in a toolbar with class `vp-bar`, while the theme styles toolbar buttons only under `iv-bar`, so they fall back to the browser's default look; and the docgen pages turn on the pan-zoom library's built-in controls, which it draws with its own fixed colours.

## Fix intent

The UX mock and all zoom and pan controls must follow the selected light or dark theme, using the shared theme's colours, and stay readable in both. Zoom and pan must keep working as they do today on every page type, including the docgen fallback page. Pages that are already generated keep their current styling until they are regenerated. The fix must confirm the result by rendering real pages in both themes.
