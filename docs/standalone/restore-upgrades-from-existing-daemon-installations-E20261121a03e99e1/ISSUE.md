# Restore upgrades from existing daemon installations to the owned runtime

## Reproduction

1. Start with an existing source daemon installation created before the owned-runtime change, such as a30aa7f91, and invoke its normal IDE/TUI/daemon update path. The installed scripts/daemon-ctl.sh still calls bare npm for install/build. An isolated routing reproduction copied that exact installed script, explicitly selected Node22 with INSRC_NODE_BIN, put a deliberately failing npm first on PATH, and ran update --skip-sync --skip-build. The ambient npm was invoked and the update exited4. This reproduces invocation routing, not an actual remote-machine native compiler failure. [[c1]] [[c2]]
2. On OrbStack Linux x64, use the real source checkout from the prior clean installation and isolated persistent state with the verified Node22.22.1 cache. Run the latest canonical packaged installer against that existing target with --migrate-runtime --no-start. It exits4 with 'existing source installation requires a staged update' before update work. The source commit, package-lock, built executable and binding state remain unchanged. The private /tmp home from the earlier test was cleared by the VM restart, so this reproduction deliberately uses isolated persistent state and does not claim to reproduce a production database migration. [[c3]]
3. Current owned-runtime-bound source updates also refuse in-place mutation. On macOS, the separate legacy migration bridge requires authenticated release/bootstrap material; a source/client-generated installer without that material cannot serve as a universal recovery command. [[c4]] [[c5]]
Expected: existing installations have a supported, documented upgrade entrypoint that obtains verified matching Node/npm and the native build environment before npm executes, then stages and validates the candidate before activation. Updating files must not require a successful build under the old runtime first. Installations left with newer source but stale compiled output or partial dependencies after a failed update must be handled explicitly. [[c6]]
The user's exact other-machine npm/compiler error is still requested. Do not attribute every reported build failure to one cause without that log. [[c7]]

## Root cause

The new runtime/build ownership is available only after an updated entrypoint reaches it. The current resolver prefers the target installation's helper, and current update paths can delegate to scripts already installed in the old checkout. Replacing repository files does not replace the already-running old updater's functions or npm command selection. Correctly choosing NODE_BIN for daemon/helper launches therefore does not establish matching npm execution in that old updater. [[c1]] [[c2]] [[c4]]
The shared staging implementation does select absolute owned Node/npm, but that does not prove end-to-end reachability from historical installed clients. Linux source installations have an explicit existing-target refusal rather than a completed staged-upgrade route; the advertised --migrate-runtime mode does not implement that missing route. The legacy preparation controller is Darwin-specific and requires its existing authenticated source/compatibility machinery. These safety requirements must remain enforced. [[c3]] [[c4]] [[c5]] [[c8]]
Prior runtime qualification proved real fresh installations plus component-level failure, recovery and routing behavior. Existing routing tests use stub Node/npm/authorization delegates, so they do not establish a real historical installation upgrading through each user-visible entrypoint with actual native dependencies. The completed runtime work did not deliver that full upgrade qualification. [[c6]] [[c9]]

## Fix intent

Provide one coherent supported upgrade/migration flow for existing legacy and runtime-bound source installations on the already-qualified macOS/Linux targets. Bootstrap the verified toolchain independently of rebuilding the old installation, route user-visible update entrypoints through it, and ensure absolute matching Node/npm plus Python bytecode protection and the unset-only ONNX CUDA default reach native install/build processes. Preserve explicit user environment choices. A legacy version may require a newly delivered independent bootstrap; specify and test how that bootstrap is reached rather than assuming old running code acquires new behavior automatically. [[c4]] [[c8]]
Stage and validate before selecting or stopping the existing installation; preserve user data, source changes, authenticated release verification, compatibility/floor/rollback checks and referenced runtimes. Diagnose partly failed old updates and provide an explicit supported recovery path; do not delete databases, bypass signing, relax runtime inventory checks, or silently re-enable in-place updates. Keep signed managed bundles distinct from source installations and reuse existing lifecycle/staging components wherever they satisfy the target contract. [[c4]] [[c5]] [[c8]]
Qualify real historical-install-to-current upgrades and a subsequent update of a migrated install through applicable IDE, TUI/CLI, daemon and standalone-installer paths. Exercise absent/20/26/hostile ambient runtimes, actual npm/native builds, missing bootstrap material and failures before cutover; verify selection/data preservation, rollback/retry and child closure. Use OrbStack for Linux and actual macOS coverage; mocked delegates alone are insufficient. Remote-machine logs remain an input to the final diagnostic matrix. This correction does not broaden Windows support or implement the separately logged macOS IPC-stop fallback. [[c6]] [[c7]] [[c9]]
