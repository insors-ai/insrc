What changed vs. today: the panel renders two plain HTML tables — a 34-row "Role tiers" table (one row per role, no structure) and a 1-row "Core floor" table — plus a flat checkbox list for Providers. There's no grouping, so scanning 34 roles for the handful you actually want to override means scrolling past all of them.

What this mock proposes: roles split into two collapsible groups by their existing criticality field (critical/peripheral — already in the data, no new concept) — critical open by default since those are floor-protected and most likely to be reviewed, peripheral collapsed; a "show N more" link rather than rendering all rows for a group at once; Providers as status cards (chip = registered / not registered / CLI unavailable) instead of three different checkbox states.

Open questions for round 2: (1) collapsible sections need a tiny bit of client JS (a <details>-like toggle) — fine since the panel already has a bootstrap script, just confirming it's in scope; (2) is "show N more" good enough, or do you want a text filter box for the 34 roles; (3) keep the groups as critical/peripheral, or split further by the (A)/(B)/(C) categories in the role-taxonomy comments (pipeline reasoning / workflow+review+build+tracker / indexer summarisation) — the latter needs the taxonomy file to actually carry a category field, which it doesn't today.
