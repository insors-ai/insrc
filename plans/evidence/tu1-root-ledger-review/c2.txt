 06 / TOKEN SEMANTICS Normalize before adding. Counter Meaning / arithmetic inputUncachedTokens Input processed without a cache hit, excluding cache reads and cache writes under this normalized contract. cacheReadTokens Input served from cache; a separate input bucket. Count once even if native input totals include it. cacheWriteTokens Input written to cache; separated from both uncached input and cache reads. outputTokens All generated output, including reasoning when the native provider includes it. reasoningTokens Informational subset of output. Never added again to processed tokens. If native output excludes reasoning, the adapter must normalize output to an inclusive value first. Processed tokens = uncached input + cache read + cache write + output Reasoning tokens ⊆ output; do not add them a second time. Adapters must declare and test native semantics. Example: inclusive input 10,000 with 6,000 cached normalizes to 4,000 uncached + 6,000 cache-read. A native report that already excludes cache must not be subtracted again. Unsupported cache metrics are zero only when the provider contract establishes that no such consumption occurred; otherwise they remain unknown. Counts from different tokenizers are useful workload totals, not equivalent effort or monetary units. Per-call observations are preferred. Session-cumulative counters must be differenced against a durable baseline within the same native session/model; a missing baseline, counter reset or model change makes the delta unknown until reconciled. Never sum successive cumulative snapshots. If a CLI reveals only per-model totals for one invocation, retain that granularity and model slice with physical call count unavailable . When leaf calls and a CLI aggregate overlap, choose exactly one non-overlapping accounting basis per invocation/model. The aggregate is fallback evidence, not additional usage. A later decomposition must append an explicit reconciliation that excludes the fallback from addition while retaining its provenance. The initial event schema will require a versioned reconciliation extension before supporting mixed overlapping observations; it must not silently ingest both. An aggregate-only integration does not satisfy the product’s complete per-call coverage claim. Reported / estimated / unknown stay separate. Default totals sum provider-reported values and show ≥ with “Partial” if components are unknown. Estimates are disclosed separately and included only with an explicit control; then use ≈ and label the estimate portion. If unknown usage also remains, show “≈ known + estimates + unknown”; an estimate is not a strict lower bound. Pending means a durably recorded start without a terminal observation; unavailable means a terminal/interrupted attempt whose usable counters are absent. Neither is measured zero. A genuine instrumented zero is 0 . Legacy absence is “Not recorded”. A model not confirmed by the response remains “Requested model; actual unavailable”, not an asserted actual model. 08 / DURABILITY & INTEGRITY Usage history survives independently of artifact writes. Requirement Acceptance behavior Append-only, idempotent writer Serialize per-root appends through the daemon-owned usage ledger service. Stable event IDs survive retries. An identical duplicate is acknowledged without another charge; a different payload reusing that ID is a conflict, not last-writer-wins. Crash recovery A started event is durable before dispatch. Recover staged Avro appends and pending root/child identity reservations after restart. A crash after dispatch without usable counters leaves an interrupted/unknown attempt; no model re-execution just to collect telemetry. Preserve on rewrite / revision Artifact writers and codecs do not own usage bytes. Artifact import/export must explicitly include or disclose missing root-ledger data; regeneration and approval leave ledger bytes intact. Usage-only appends do not change description/body/citations hashes, invalidate approval, or reset content revision. They advance a separate usage sequence/watermark. Failed recording Surface the capture failure and retain completed result/recovery evidence. Retry the append, not the model call. If capture cannot durably record a new start, refuse that dispatch with a recoverable accounting error rather than knowingly starting an untraceable call. Git / concurrent branches Binary ledger files must not be merged as text. Import branch histories through the daemon, union immutable events by stable ID and validate root/owner/call identity. File offsets and timestamps are not identities. Concurrent edits or forked corrections remain visible conflicts until reconciled; do not discard either branch. Corrections A correction replaces a complete observation; it is not an additive charge. Preserve the original. Use the last unambiguous valid correction chain; cycles, forks, mismatched owners or nonexistent targets produce partial/conflict notices. Data retention Keep usage across rejected designs, retried steps, cancelled runs and artifact supersession. An explicit deletion/retention policy must preserve a tombstone/retained accounting owner; silent loss cannot look like reduced historical consumption. The existing content hash covers description, body and citations. Root-ledger appends leave artifact files intact; implementation must verify independent freshness, root identity and paired import/export behavior. On first adoption, do not backfill guesses. Allow a source-verified import as explicitly marked provenance, with deduplication against existing native IDs. Store bounded normalized facts, not raw prompt/response transcripts. Existing provider access remains through local CLI OAuth or local Ollama.
