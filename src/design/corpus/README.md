# Corpus foundation (sc1/sc2)

Import the pure API from `index.js`. It uses no filesystem, database, daemon, network or LLM provider. It does not import sources, install or publish releases, activate guidelines, or grant approval.

- `decode*` functions check closed runtime schemas without coercion or field stripping.
- `validateGuidanceRecord` checks complete content and its deterministic version. Draft mode permits a draft review; publication mode requires content-bound review metadata and a supplied specimen inventory.
- `validateRelease` checks a caller-supplied immutable in-memory manifest/file inventory, regular-file membership, portable paths, raw file hashes, record versions, exact acyclic relationships and the coverage envelope binding. Specimens must be separate from metadata and record files.
- `checkPublication` also requires exactly one successful, current internal assessment from each downstream stage (`eligibility` and `coverage`). These are adapter results, never user-issued authorization tokens. `eligible` is a preflight result, not persistent publication.

Record content → candidate content → coverage review → release manifest is the hash order. Candidate identity binds the complete manifest except releaseId, reviewDigest, and the unique coverage entry’s digest. Coverage path and mediaType remain bound. Stage that entry before hashing; its placeholder digest is ignored until coverage bytes exist. Zero or multiple matching entries yield an empty internal candidate identity, so preflight rejects all supplied assessments as stale while retaining an independently computable manifestDigest. Original authors may omit sources. Unsourced inferred guidance must explicitly declare an independently authored/inferred/developed rationale with author attribution; downstream eligibility still assesses the declaration.

Release diagnostics address `/manifest/...` or `/files/...`. Errors inside decoded JSON point to the containing file's `/bytes`, with the decoded field pointer in the message. Assessment composition additionally uses `/assessments`. Hash functions reject unsafe/non-JSON data; validators turn expected input failures into deterministic issues.

## Reviewed source ingestion (sc3)

Import pure schemas, policy, lineage, notices and assessment from `sources/index.js`. Local Git acquisition is a separate entry at `sources/git-reader.js`; orchestration is `sources/stage.js`. Neither I/O entry is exported by a pure barrel. No database migration, daemon registration, network fetch or installed corpus is required by these new modules.

A maintainer supplies a versioned `SourcePolicy` separately from repository contents. Each exact file profile binds a canonical HTTPS/SSH repository URL (without credentials), full 40/64-character commit ID, upstream path, raw SHA-256 digest, reviewer, resolved category/terms, evidence digests, attribution and redistribution/modification conditions. MIT/Apache-2.0/CC0 IDs do not authorize files by themselves. Fonts and compound license choices require explicit reviewed profiles/categories with nonempty recorded conditions (including an explicit reviewed absence of special restrictions where applicable). This code applies recorded decisions; it does not interpret licenses or infer rights.

1. Call `stageLocalSources(policy, [{ localRepository, request }])` with an existing absolute local repository and a request containing `repositoryUrl`, `revision`, selected `paths` and explicit UTC `retrievedAt`. Only commit/tree/blob objects are read; worktree changes, branches, filters, replacement refs and lazy fetching cannot change the bytes. Selected unsafe paths fail before I/O. Symlinks/submodules fail; LFS remains unresolved. Unknown or stale reviewed terms/evidence remain unresolved, while independent eligible files survive. Reports contain rejected paths; returned byte snapshots contain only admitted material and its evidence.
2. Author output records/specimens and a reviewed `Lineage` descriptor. Each imported/derived output binds its exact digest, all contributing source IDs, transformation, reviewer and modification notes. Original/inferred outputs need explicit author/rationale declarations; a source-derived inferred record carries those in its binding’s `inference` field. Record sourceRefs and modificationNotes must equal the union for the record and its specimens. `validatePackagedLineage` compares distributed claims with the separate reviewed descriptor; it cannot discover undisclosed contributors by semantic inference.
3. Declare record entries, output media types, source/notices paths and exactly one coverage path/mediaType entry in the `ReleaseManifest`. A placeholder coverage digest is sufficient here. Call `prepareEligibilityCandidate(manifest, outputBytes, { policy, imports: staged.imports, lineage })`. It returns metadata/evidence/lineage bytes, the assembled manifest and a passing candidate-bound eligibility assessment, or validation issues. No declared output is silently dropped.
4. S003 supplies the real editorial coverage envelope. Add its exact bytes/digest, compute `reviewContentDigest`, then `releaseContentDigest`, and run S001 `checkPublication` with independently produced eligibility and coverage assessments. S004 owns durable package/catalog installation; S005 owns publication policy. No guideline authoring or activation happens here.

`assessEligibility` can independently reassess an assembled candidate from the original reviewed policy, acquired bytes and reviewed lineage. It reconstructs expected source metadata, notices and evidence rather than trusting staged eligibility labels. Internally it uses a private minimal coverage envelope solely to run S001 structural validation before editorial review; that envelope is never returned or a coverage approval. Zero/duplicate coverage entries return failure without an empty assessment identity.

`sources/lineage.json` is a fixed inventory entry. The source manifest and NOTICE retain exact pinned identities and all obligations; `sources/evidence/<sha256>.txt` contains unchanged UTF-8 evidence, deduplicated by digest while preserving associations. NOTICE is versioned UTF-8 text with canonical JSON metadata, including redistribution conditions and modification requirements. Metadata/evidence categories derive from manifest roles and reviewed sources, not arbitrary output declarations. Evidence BOMs/newlines are preserved; binary assets are never decoded as text.

Acquisition is bounded to 10,000 paths and 64 MiB source/evidence bytes, with a separate 64 MiB verified metadata cache, 64 KiB stderr, 30 seconds per child and five minutes for the complete pinned-source request. Limits may be lowered for tests or maintenance. Shared evidence paths are read once per request; distinct source paths count separately. Errors release subprocess resources and return no partial admitted result. Requests, blobs, policies and output declarations are copied or decoded before validation; no clock or provider is involved.
